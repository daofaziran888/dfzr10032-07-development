# 多源数据采集与RPA自动化平台

面向网页抓取、API接入、增量采集、RPA流程编排、数据校验与采集监控的数据工程平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## RPA采集结果数据集（rpa_dataset）

把 RPA 任务的页面定位器与结果字段落成可交付、可回查的采集产物，后端规则集中在
`app/services/rpa_dataset.py`，页面分三个页签：字段定义版本、采集结果、接入记录。

- **字段定义版本**：同一任务只保留一个「生效中」版本；登记新版本时旧版本自动「已归档」。
  批次仍在提取期间收到不同版本的字段定义时，已建采集记录冻结其采用版本的完整字段快照
  （含动作位置、定位器、是否必填），取值口径不随定义改版漂移，之后新建记录才采用新版本。
- **采集结果记录**：按任务编号 + 执行批次 + 页面标识从可重复读取的页面提取字段，
  每条记录保留动作位置与执行批次。必填字段定位失败时，记录置为「定位失败」，
  `失败明细` 带具体字段、动作位置与定位器，字段值不会作为正常空值交付，也不能确认进入接入通道；
  可执行「重试提取」清空旧失败值后重新提取。
- **单条确认约束**：重试同一页面时，同一（任务编号、执行批次、页面标识）下只允许一条「已确认」记录，
  后确认的记录把旧记录顶替为「已顶替」；已接入通道的页面禁止再确认新记录。
- **批次提交接入通道**：`POST /api/rpa_dataset/submit` 按任务编号 + 执行批次整批提交，
  仍有「提取中/定位失败」记录或没有已确认记录时拦截；通过后按每个页面生成一条与原页面关联的
  接入记录（`rpa_ingestion_record`，含页面地址、动作位置、字段定义快照与采集值），批次不可重复提交。
- **批次完整回查**：`GET /api/rpa_dataset/trace?task_code=&batch_no=` 一次返回该批次采用的
  字段定义版本、全部页面采集记录与接入记录及状态汇总，保证每份交给接入通道的批次都能按其
  采用的字段定义完整回查。
